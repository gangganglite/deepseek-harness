## 目标与范围

用户交办的任务需要访问服务器时，Harness 可以调用插件使用本机 XTerminal 已保存的连接。例如，用户让 Harness 检查测试环境的服务状态，Harness 可以查找匹配的服务器并发起任务所需的连接，用户无需另外发出「连接服务器」指令，也无需事先知道 XTerminal 数据库的位置。

优先由插件在本机完成认证和建连，并把已建立的连接交给 Harness 使用。Harness 无需单独配置或保存用户名、密码、私钥及口令。名称、主机和端口用于识别目标，后续远程操作按原任务的授权范围执行。

需要由 Harness 发起连接时，备选方式是由插件提供临时连接引用。Harness 在本机将引用交回插件，由插件为对应目标完成认证。引用只对获授权的任务和目标有效，到期或任务结束后失效。临时连接引用和本机读取的认证材料留在本机运行时，禁止通过认证流程进入模型请求、工具输出、日志或 Session。两条路径对 Harness 的调用方均只要求选择目标并取得可用连接。

首版支持两种 XTerminal 已保存的 SSH 认证方式：用户名与密码、用户名与私钥。需要口令且本机能够取得口令时，私钥口令同样留在本机认证流程。凭据不可用时，报告认证受阻。

首版使用 TypeScript，运行于 Harness 的 Node.js 环境。插件显式启用后即可尝试发现 macOS 本机的 XTerminal SQLite 数据库，无需预填路径。服务器管理和配置导出不在本次范围内。

## 用户流程与行为

| 场景 | 行为与反馈 |
|---|---|
| 任务需要访问服务器 | Harness 根据任务已有的名称或地址查找服务器。目标明确且访问在任务授权范围内时，优先由插件建立连接。需要由 Harness 发起时，通过本机临时连接引用完成认证。连接就绪后，Harness 继续原任务。 |
| 同一任务访问多台服务器 | 每条远程命令都显式指定目标。任务可以保留多条目标连接，连接或操作其他服务器不改变已提交命令的目标。 |
| 等待命令批准 | 审批绑定这次调用的目标和命令。等待多久本身不使审批失效。批准后，只要调用仍有效且该目标的原连接可用，就直接执行。若连接已关闭，报告该目标的连接不可用。 |
| 目标不明确 | 当多条记录均可能匹配，或任务未提供足够信息时，呈现可区分候选的名称、主机和端口，等待用户选定。 |
| 列出或查找服务器 | 支持按名称或主机查找，也可列出保存的服务器。返回名称、主机、端口及分页信息。无匹配时提示「未找到匹配的 XTerminal 服务器。可以换一个名称或主机地址再试。」 |
| 首次使用，尚未配置路径 | 插件先自动发现本机 XTerminal SQLite 数据库。发现并验证成功时自动保存路径，继续当前操作。 |
| 尚未配置且自动发现失败 | 返回「尚未配置 XTerminal 数据库路径。请查找本机 XTerminal 的 SQLite 数据库并设置路径。」模型找到候选后可以提交。插件只读验证，通过后首次保存。 |
| 已保存路径 | 后续会话和重启复用已保存的路径。已经自动发现或补录成功时，模型无需再设置，设置工具也不能覆盖。已保存路径失效时，提示检查本机配置。 |
| 远程命令输出超过 3000 字 | 保存本次完整输出到 Harness 可按需读取的文件。工具响应最多 3000 字，末尾提示「部分输出已省略。完整输出保存于 {路径}，可按需读取。」 |
| 数据源或连接不可用 | 区分找不到可用数据库、目标不明确、主机身份校验失败和认证失败。提示当前阻塞及可采取的下一步。反馈省略底层错误、原始记录和认证数据。 |

路径记录只保存定位数据库所需的信息。插件对自动发现和模型提交的候选使用同一套只读验证。XTerminal 数据库及已保存的路径均不通过模型修改。服务器记录里的备注、快捷命令及原始连接配置不得进入模型上下文。远程命令输出保留原文，用户名可以出现在远端正常返回的输出里。认证流程的内部数据和诊断不作为命令输出。

## 验收条件

| 编号 | 条件与操作 | 可判定结果与验证方式 |
|---|---|---|
| AC-1 · 查询与目标识别 | 用多条服务器记录验证列表、名称和主机筛选、翻页、无匹配及多条匹配。 | 结果只包含名称、主机、端口和必要的分页信息。源数据未变时翻页无重复或遗漏。无匹配及目标不明确有对应反馈。 |
| AC-2 · 凭据隔离与只读 | 用含测试哨兵的用户名、密码、私钥、口令、备注、快捷命令及连接配置验证查询和连接。 | 查询以只读模式使用数据库，应用层的查询投影仅含允许的三个字段。连接所需凭据仅供本机认证流程使用。认证流程不得把哨兵写入命令结果、完整输出文件、错误、日志、模型请求或 Session。远端命令正常返回的用户名按原文呈现。源记录保持原样。 |
| AC-3 · 错误与权限 | 模拟数据库缺失、不可读或记录损坏，提交无效路径，并尝试通过查询参数切换数据源、运行命令或发起连接。 | 发现无法恢复时返回安全错误。无效路径不得写入，已配置时拒绝模型覆盖路径。查询参数无法更换数据源或触发其他操作。 |
| AC-4 · 任务驱动的连接 | 分别使用密码和私钥认证的 XTerminal 记录，通过 Harness 交办需要访问指定测试服务器的任务，省略独立连接指令。再分别让目标不明确、主机身份校验失败和认证失败。 | 正例中 Harness 找到目标、获得可用连接并继续原任务。目标不明确时等待选择，校验或认证失败时报告阻塞并停止依赖该连接的步骤。 |
| AC-5 · 路径发现、首次补录与复用 | 分别验证首次自动发现成功、自动发现失败后模型首次补录、无效候选、已配置后再次设置、重启及已保存路径失效。 | 自动发现成功后直接保存和使用。自动发现失败且尚未配置时，模型可提交候选并在验证通过后保存。无效候选不写入，已配置时任何补录请求均不覆盖原路径。重启后复用有效路径，路径失效时提示检查本机配置。 |
| AC-6 · 本机连接交接 | 验证插件建连后 Harness 能接续原任务。若交付备选路径，再验证正常引用、到期引用、跨任务使用和替换目标。 | Harness 通过选定目标取得连接，无需另行配置认证材料。备选引用只在对应任务与目标下有效，到期或越权使用时无法连接。工具输出和 Session 中无可用于发起连接的引用。 |
| AC-7 · 远端输出截断与续读 | 分别执行产生少于、恰好和超过 3000 字输出的命令，检查响应与完整文件，并从 Harness 读取文件。 | 未超限输出按原文呈现。超限时工具响应含提示在内最多 3000 字，末尾说明省略并给出可读路径。文件保留本次完整输出。若文件保存失败，明确报告，避免给出无效路径。 |
| AC-8 · 按目标执行与审批 | 同一任务建立 A、B 两条连接。提交 A 的命令并等待审批，在审批期间使用 B，再批准 A。另验证原连接关闭和调用取消。 | A 的命令只在 A 的原连接上执行，B 可以独立使用。等待审批和操作 B 都不会改变 A 的目标。原连接关闭或调用取消时，本次命令不执行。 |

## 技术设计待验证

技术设计先验证插件建立的连接能否交给 Harness 消费。若需备选路径，验证插件能否为 Harness 发起的连接提供本机认证，同时保持相同的调用方式。现有 `dsh-ssh` 依赖预配置的 OpenSSH 别名，连接交接和临时引用均需验证接入。两种认证方式都需验证 XTerminal 保存的凭据能否通过本机支持的方式取得并用于认证。

复用现有 Harness 输出文件能力前，需验证它能按字符限制内联响应、保证完整输出可读，并在文件保存失败时遵守长度上限。
